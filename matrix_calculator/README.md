## Вариант 29

Решение: `matrix_count_nonzero` в `src/matrix.cpp`; интерфейс — `include/matrix.h`;
пример использования — `src/main.cpp`.

Контракт: считаются элементы, для которых `fabs(value) > threshold`.
Порог конечный и неотрицательный; равенство порогу не учитывается. Использование
модуля соответствует понятию ненулевого элемента для положительных и отрицательных чисел.
Для матрицы `{0, 1e-10, -2; 3.5, -1e-9, 0; 4, -5, 0}` при пороге `1e-9` ответ — 4.
NaN-элементы не учитываются, поскольку сравнение с NaN ложно; бесконечные элементы
превышают любой допустимый конечный порог.

## Управление памятью

Матрица имеет требуемые поля `double** data`, `int rows`, `int cols`.
Размеры должны быть положительными, все строки — выделенными.
`matrix_from_array` копирует данные; операции создают новые матрицы.
Каждое выделение нужно освободить ровно один раз через `free_matrix`.
Передача `Matrix` по значению копирует указатели: освобождение не обнуляет
структуру у вызывающего кода. Повторное освобождение допустимо только для изначально
пустой структуры `{nullptr,0,0}`. При частичном сбое выделения память освобождается.
Демонстратор и тестовый fixture освобождают все зарегистрированные матрицы автоматически.

## CI/CD

Workflow: `../.github/workflows/matrix-ci.yml`. При изменении этой лабораторной запускаются:
сборка, 23 теста Google Test и демонстрационный CTest (всего 24), Valgrind,
Doxygen, сборка и запуск Docker. HTML-документация и вывод контейнера публикуются
как артефакт GitHub Actions. CI проверяет изменения, доставка артефакта реализует CD;
публикация в Docker Hub и автоматическое развёртывание не требуются заданием.
